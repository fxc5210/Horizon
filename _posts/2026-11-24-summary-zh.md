Ladybird 独立网页浏览器项目已正式发布首个 Alpha 版本，用户无需自行编译即可在 macOS 和 Linux 系统上安装使用。该版本引入了多进程架构、全新的 JavaScript JIT 以及 Cranelift WebAssembly 引擎，并在网页平台测试（WPT）中取得了显著进展。尽管项目使用或借鉴了 SerenityOS 以及 Skia、SQLite 等部分外部组件，但其核心的 HTML 解析、CSS 引擎、布局和 JavaScript 实现均为独立构建。官方提示称当前版本仍处于 Alpha 阶段，部分网站可能无法正常运行并伴随崩溃风险。

### [智谱 AI 发布 GLM-5.4，引入首个循环 Transformer 架构](https://z.ai/blog/glm-5.4) ⭐️ 8.0/10

中国人工智能实验室智谱 AI 发布了 GLM-5.4 模型，主打面向通用编程任务。该模型是其首个采用循环 Transformer（Loop Transformer）架构的系统，通过让一组权重共享的层运行多次迭代来精炼隐藏状态，从而在不增加参数量的情况下实现更深的网络。目前该模型尚未以开源权重形式提供，用户需订阅 Z.ai 的 Coding Plan 才能通过其与 OpenAI 兼容的 API 访问。

hackernews · foohis · 11月23日 10:06 · [社区讨论](https://news.ycombinator.com/item?id=50609685)

**「背景」** 传统 Transformer 的每一层在每次前向传递中仅运行一次，其架构类似于未展开的循环。循环架构通过复用权重层来优化高带宽内存（HBM）与芯片之间频繁搬运权重的硬件瓶颈。

**「影响与兼容性」** 开发者无法通过普通 API 或 OpenRouter 访问 GLM-5.4，必须注册特定的 Coding Plan 订阅并使用兼容 OpenAI 格式的 Responses API 端点。开发者社区已开始适配该模型的接口插件。

**「社区讨论」** 评论者对智谱 AI 公开模型架构细节的透明度表示赞赏，认为循环 Transformer 是当前前沿大模型的发展方向之一。不过也有用户指出，中国模型的“马拉松式思考”在处理简单任务时会进行过度思考，导致等待时间显著增加。

### [Anthropic 称内部 Claude 模型发现 VP≠VNP 并公开 Lean 4 证明](https://github.com/anthropics/formal-math/blob/main/vp-vnp/README.md) ⭐️ 8.0/10

Anthropic 于 2026 年 11 月 24 日公开了题为《VP ≠ VNP over every field》的论文及对应的 Lean 4 形式化证明。仓库信息显示该结果由内部研究用 Claude 模型发现，论文与代码均由 AI 撰写，证明了哈密顿圈多项式的超多项式算术电路下界并得出 VP 是 VNP 真子类的结论。不过，目前该成果仅完成了标准公理审计与独立内核复核（除预留文件外无 sorry），尚无人类数学家通读，Lean 也无法自动确认形式化陈述与声称命题完全一致，仍需等待独立审阅。

telegram · zaihuapd · 11月24日 06:02

**「背景」** 代数复杂度理论中的 VP 与 VNP 问题是由 Leslie Valiant 于 1979 年提出的猜想，旨在区分可在多项式大小算术电路中计算的多项式族（VP）与可用多项式大小算术电路投影并求和的多项式族（VNP），其地位类似于计算机科学中的 P 与 NP 问题。

**「影响」** 如果该形式化证明经独立数学界审阅确认无误，将解决 Valiant 于 1979 年提出的代数复杂度猜想（针对算术电路的 VP 与 VNP 关系），并标志着 AI 在复杂形式化数学证明领域取得重大突破。

### [Nari-Labs 发布 NariQ：10 GB 文件大小实现接近 BF16 性能的 Qwen3.8-27B 量化模型](https://huggingface.co/nari-labs/Qwen3.8-27B-NariQ-GGUF) ⭐️ 7.0/10

Nari-Labs 推出了 NariQ 量化方案，将 Qwen3.8-27B 模型压缩至 3 位或更低比特（约 10 GB 文件），并声称在智能体任务、数学、多语言推理和图像理解等基准测试中保持了接近 BF16 的性能。根据官方公布的数据，3 位和 2.5 位量化版本在 DeepSWE、Terminal-Bench 2.1、AIME 等多项基准上达到了与未量化 BF16 相当甚至略高的表现。运行这些模型目前需要使用其定制的 llama.cpp 分支。

hackernews · toebee · 11月23日 13:42 · [社区讨论](https://news.ycombinator.com/item?id=50611402)

**「背景介绍」** 大型语言模型量化旨在通过降低每个参数的比特数来减小模型文件体积和内存占用，以便在消费级硬件上运行。然而，极低比特（如 3-bit 或更低）量化通常会导致模型在复杂推理和长周期任务上的性能显著下降。

**「影响与兼容性」** 开发者和自托管用户现在可以在约 10 GB 的文件体积下运行 27B 级别的模型，并在标准硬件上进行测试。但需要注意，目前必须使用 Nari-Labs 的 llama.cpp 分支才能运行该模型。

**「社区讨论」** 社区成员对这种超低比特量化方案表现出了兴趣，部分用户赞赏其测试了长周期任务等实用指标，但也有人对基准测试的泛化能力、信息丢失以及在 Apple M 系列芯片上的运行速度（如 M3 Pro 上解码较慢）提出了质疑和讨论。
